# خانه‌گی — فروشگاه آنلاین لوازم خانگی

پلتفرم فروشگاهی حرفه‌ای و فارسی (RTL) برای لوازم خانگی، ساخته‌شده به‌صورت تمام‌عملیاتی: دیتابیس واقعی، احراز هویت، سبد خرید سمت سرور، ثبت سفارش، موتور قیمت‌گذاری بر پایه نرخ ارز و پنل مدیریت کامل.

> ⚠️ **نشان‌گذاری داده‌های نمایشی:** تمام محصولات، برندها، نظرات، سفارش‌های نمونه و اطلاعات تماس، داده‌های نمایشی (Seed) هستند و با برچسب `[نشان‌گذاری آزمایشی]` مشخص شده‌اند. قبل از انتشار واقعی جایگزین شوند.

## ✨ امکانات

### فروشگاه (مشتری)
- صفحه اصلی: هرو، دسته‌بندی‌ها، محصولات ویژه/پرفروش/جدید/تخفیف‌دار، بنرهای تبلیغاتی، برندها، نشانه‌های اعتماد، «بازدیدهای اخیر»
- فهرست محصولات: فیلتر (برند، محدوده قیمت، موجودی، تخفیف‌دار)، ۶ حالت مرتب‌سازی، صفحه‌بندی، هم‌گام‌سازی کامل فیلترها با URL
- صفحه محصول: گالری با زوم، تنوع‌ها (رنگ/ظرفیت) با قیمت اضافه، مشخصات فنی، نظرات و امتیاز، محصولات مشابه، JSON-LD
- جستجو با پیشنهاد زنده (نام/SKU/مدل/برند — فارسی و لاتین)
- سبد خرید مهمان (کوکی) با ادغام خودکار پس از ورود؛ **قیمت‌ها همیشه سمت سرور اعتبارسنجی می‌شوند**
- تسویه‌حساب ۳ مرحله‌ای (آدرس → ارسال → بازبینی) با کد تخفیف و ارسال رایگان بالای آستانه
- حساب کاربری: سفارش‌ها با تایم‌لاین وضعیت، آدرس‌ها، پروفایل، تغییر رمز، علاقه‌مندی‌ها، مقایسه (تا ۴ محصول)
- درگاه پرداخت **آزمایشی** با برچسب شفاف «حالت تست — هیچ پول واقعی جابه‌جا نمی‌شود»
- صفحات محتوایی: درباره ما، تماس، سوالات متداول، شیوه ارسال، بازگشت کالا، حریم خصوصی، قوانین، گارانتی + صفحه ۴۰۴

### پنل مدیریت (`#/admin`)
- داشبورد: KPI ها (سفارش‌ها، درآمد سفارش‌های پرداخت‌شده، در انتظار، مشتریان)، کم‌موجودها، پرفروش‌ها، سفارش‌های اخیر، لاگ فعالیت مدیران
- محصولات: CRUD کامل با تصاویر، مشخصات، تنوع‌ها، قیمت‌گذاری دستی/ارزی، فعال/غیرفعال‌سازی
- سفارش‌ها: فیلتر و جستجو، جزئیات، **گذار وضعیت با اعتبارسنجی نقله** (Transition Map)، یادداشت مدیریتی
- قیمت‌گذاری: ثبت نرخ ارز دستی (با هشدار «نرخ قدیمی»)، قواعد حاشیه سود (سراسری/دسته/برند/محصول)، **پیش‌نمایش قبل از اعمال**، تاریخچه قیمت
- موجودی: ورود/خروج/اصلاح شمارش با دلیل + تاریخچه حرکات
- کدهای تخفیف: CRUD با سقف استفاده هر مشتری
- **نظرات**: صف مودریشن (تأیید/رد + پاسخ مدیر + نشان «خرید تأییدشده»)
- **کاربران**: جست‌وجو، آمار خرید، مسدود/رفع مسدودی، تغییر نقش با گاردهای امن (عدم حذف آخرین مدیر)
- **گزارش فروش**: بازه روز/هفته/ماه با نمودار SVG و KPIهای واقعی دیتابیس
- **تنظیمات فروشگاه**: تماس/سئو/تجارت + مدیریت روش‌های ارسال
- **خروجی/ورود داده**: CSV از ۱۰ موجودیت (UTF-8 سازگار Excel) + ورود گروهی محصولات با پیش‌نمایش و گزارش خطا
- **سایر**: کد رهگیری سفارش، فاکتور چاپی، حذف نرم محصول، عملیات گروهی، آپلود تصویر با Alt، sitemap.xml پویا

## 🏗 معماری و پشته فناوری

| لایه | فناوری |
|---|---|
| فریم‌ورک | Next.js 16 (App Router) + TypeScript 5 |
| UI | Tailwind CSS 4 + shadcn/ui + lucide-react + Vazirmatn |
| State | TanStack Query 5 (سرور) + Zustand (UI) |
| دیتابیس | Prisma ORM + SQLite (محلی) / PostgreSQL + Supabase (تولید — docs/supabase-setup.md) |
| احراز هویت | نشست سمت سرور (scrypt + کوکی httpOnly) / Supabase Auth (اختیاری، با fallback خودکار) |

**تصمیم‌های کلیدی (شفاف):**
1. **Supabase (PostgreSQL + Supabase Auth) به‌صورت گزینه‌ای پشتیبانی می‌شود** — با تنظیم متغیرهای محیطی، دیتابیس به Postgres ابری سوئیچ می‌شود (`prisma/schema.postgres.prisma` + `supabase/migration.sql` + `supabase/rls-policies.sql`) و ثبت‌نام/ورود از Supabase Auth عبور می‌کند؛ بدون تنظیمات، همان auth محلی scrypt کار می‌کند (fallback امن). راهنمای کامل: `docs/supabase-setup.md`. در هر دو حالت، تمام دسترسی به دیتابیس فقط از طریق API Route های سمت سرور است و مجوزدهی نقش‌محور (`CUSTOMER/STAFF/ADMIN`) در لایه API اعمال می‌شود.
2. **SPA داخل یک مسیر (`/#/...`)** — محیط پیش‌نمایش فقط مسیر `/` را نمایش می‌دهد؛ ناوبری با hash-router قابل اشتراک/بوکمارک است. برای SEO کامل مبتنی بر SSR کافی است ویوها به Route های واقعی Next منتقل شوند (زیرساخت DTO ها آماده است).
3. **پول = عدد صحیح تومان** — هیچ محاسبه مالی با اعشار انجام نمی‌شود. قیمت هر قلم سفارش به‌صورت Snapshot ذخیره می‌شود.
4. **قیمت/موجودی/کدتخفیف همیشه سمت سرور** بازمحاسبه می‌شوند؛ ورودی کلاینت هرگز معتبر نیست.
5. **کاهش موجودی اتمی** در `$transaction` با شرط `stock >= qty` (جلوگیری از oversell).
6. موتور قیمت‌گذاری به‌صورت **تابع خالص** پیاده شده تا تست‌پذیر باشد (اجرا تست‌ها در این محیط مجاز نیست — به «وضعیت تست‌ها» زیر مراجعه کنید).

## 🚀 راه‌اندازی محلی

```bash
bun install
cp .env.example .env          # مقادیر را تنظیم کنید
bun run db:push               # ایجاد اسکیمای دیتابیس
bun run seed                  # داده نمایشی: ۸ دسته، ۱۰ برند، ۳۶ محصول
bun run dev                   # http://localhost:3000
```

## ✅ وضعیت پیاده‌سازی و صحه‌گذاری

**تأییدشده با مرورگر واقعی (E2E):** مسیر طلایی مشتری (مرور → فیلتر → محصول → سبد → تسویه → ورود → سفارش → پرداخت آزمایشی → وضعیت تأیید)، گارد نقش‌ها (۴۰۳ برای مشتری در پنل)، داشبورد، لیست/فرم محصولات، صفحه قیمت‌گذاری با پیش‌نمایش موتور (۴ تغییر/۱۷ رد شده با دلیل)، موجودی، سفارش‌ها، فوتر چسبان، ریسپانسیو موبایل، فید ترب (JSON/CSV).

**تأییدشده با curl:** ثبت‌نام/ورود، ادغام سبد مهمان با کاربر، ۴۰۹ کمبود موجودی، اعتبارسنجی کد تخفیف، ثبت نرخ ارز.

### پندینگ (نیازمند پیکربندی خارجی)
- **اتصال واقعی Supabase** — کد و migration کامل و آماده است؛ فقط ساخت پروژه Supabase و پرکردن `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY` / `DATABASE_URL` (postgres) باقی مانده — `docs/supabase-setup.md`.
- **درگاه پرداخت واقعی** — لایه انتزاعی آماده است؛ درگاه فعلی TEST برچسب‌دار است و بدون callback واقعی سفارش را «پرداخت‌شده» نمی‌کند مگر در همان حالت آزمایشی.
- **تأیید اسپک دقیق فید ترب** — آداپتور ماژولار با اعتبارسنجی داخلی؛ فیلدها باید با مستندات رسمی ترب تطبیق داده شوند.
- **تأمین‌کننده خودکار نرخ ارز** — اینترفیس آماده؛ ورود دستی فعال است.
- **تست‌ها (Vitest/RTL)** — اجرای تست در این محیط مجاز نیست؛ منطق مالی خالص و جداشده نوشته شده تا افزودن تست‌ها بدون تغییر معماری ممکن باشد.
- **SSR برای صفحات محصول** — به‌دلیل محدودیت تک‌مسیرِ پیش‌نمایش؛ توضیح در docs/architecture.md.

## 🔐 امنیت

- هش رمز با scrypt + salt، کوکی نشست httpOnly/SameSite=Lax
- مجوزدهی نقش‌محور در **تمام** اندپوینت‌های ادمین (نه فقط مخفی‌سازی UI)
- اعتبارسنجی Zod با پیام‌های فارسی روی همه ورودی‌ها
- Rate-limit روی ورود/ثبت‌نام/کد تخفیف
- Audit Log برای اقدامات حساس مدیران
- هرگز کلیدها/رمزها در کد کامیت نمی‌شوند (`.env.example` مرجع است)
